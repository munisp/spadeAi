# Production readiness

**Overall: about 61/100.** This is a working vertical slice: deploy, run, meter, bill, suspend and resume, done end to end on BYOVM (Hetzner, DigitalOcean, Vultr, Akamai/Linode, AWS, OpenStack and Proxmox drivers on a shared cloud adapter, none yet live-tested), plus per-project private networks (WireGuard and Nebula) between hosts and encrypted off-host backups with restore, copied to a second site, and deployment into customer Kubernetes clusters through an outbound-only Helm agent, and a rehearsed automatic failover across two sites (Lagos/Abuja) plus a witness for Postgres, TigerBeetle, Temporal, Keycloak and Permify. It is not a production platform yet.

## Verified locally (scripts/e2e.sh plus unit tests)
| Area | Evidence |
|---|---|
| Auth | Keycloak OIDC JWT verification; unauthenticated requests get 401 |
| Authz | Permify checks on every org/project/service route; fails closed when Permify is down |
| Idempotency | Replaying the same `Idempotency-Key` returns the same operation; reusing a key with a different body returns 409 |
| Audit | SHA-256 hash chain; DB trigger blocks UPDATE/DELETE; `/v1/audit-events/verify` |
| Deploy | Temporal `DeployService`, then a one-time enrolment token, then the Rust agent enrols over mTLS, then the sha256-checked compose bundle is applied, then the health probe runs |
| Billing | TigerBeetle pending hold used as a funds check and voided after deploy (no double charge); hourly metering; rating; `exceeds_credits` suspends the org and records arrears; a top-up settles arrears oldest first and resumes the org |
| Capabilities | `/v1/capabilities` reports every integration; anything unimplemented or unconfigured shows as `unavailable` |
| Template CI | Lint rules plus a real docker smoke test before a version can be deployed |
| Backups | `scripts/e2e-backup.sh`: restic snapshot of the service's named volumes and stack dir (quiesced by default) to an off-host REST repository, encrypted with a per-service password sealed by the KEK; restore empties the volumes, restores and restarts, and the data matches the snapshot exactly. The gateway injects repository credentials at delivery, so they are never stored in `agent_command` (checked). Daily schedule per running service. Tenant isolation (checked): every service gets its own login (random, KEK-sealed, bcrypt in the tenant server's htpasswd), the tenant server runs `--private-repos --append-only`, so another service's login is refused and a host cannot delete snapshots, even its own. Retention (`restic forget --keep-daily --prune`) runs from the worker through a loopback-only admin endpoint; a retention failure is reported on the backup operation (`prune_error`). Deleting a service removes its login |
| Kubernetes | `scripts/e2e-k8s.sh` against a local k3s cluster: register a cluster, install `deploy/helm/spade-agent` with the one-time token, the agent enrols outbound over mTLS after checking the gateway CA pin, stores its identity in a Secret and reuses it after a pod restart. Inventory (version, nodes, CPU/memory, storage classes, ingress classes, cert-manager issuers) drives the configuration menu; bad namespaces, unknown storage classes, multi-replica RWO templates and residency violations are refused. Deploys render a restricted manifest (Namespace/Secret/PVC/Deployment/Service/Ingress/NetworkPolicy) that the agent re-validates and sha256-checks; checked: Ingress routing by host, NetworkPolicy allows same-namespace and blocks other namespaces, replica-aware billing intervals, scale 2→3, stop/start, refusal to adopt a pre-existing namespace, bound PVC for a stateful template, backup refused, namespaces removed on delete |
| Private networks | `scripts/e2e-overlay.sh`: two docker-in-docker hosts per kind. WireGuard full mesh and Nebula (lighthouse = lowest IP, per-project CA sealed with the KEK) both reach each other over the overlay; deleting a service removes it and the survivor's mesh shrinks. Host private keys never enter the command queue (checked) |

### Backup hardening (review of #9)
- The restic REST server now requires HTTP basic auth (`scripts/backup-repo-user.sh` creates the user and prints `SPADE_BACKUP_REPO`); without a user every request is 401 and the `backups` capability reports the rejected credentials. Superseded: each service now has its own append-only, private-repo login (see Backups above).
- Restore checks the snapshot is still in the service's repository and that every snapshot path is one of the service's volumes or its stack dir, restores into a staging dir with `--include` for those paths only, and only then stops the app and swaps data. Failures before the swap report `data unchanged` and keep the service state; failures during the swap mark the service `failed` instead of hiding it.
- Backing up a stopped service no longer starts it (quiesce only touches running containers).
- Backups pruned by retention are marked `pruned` and can no longer be selected for restore.
